# Навык: Модель сущностей FOnline (Entity Model)

## Синхронизация свойств (Properties)
- Изменения на стороне `ServerEngine` автоматически сериализуются через `PropertiesSerializer` и отправляются клиенту.
- При добавлении нового свойства в прототип (`.fomain`), требуй от пользователя перезапуска генерации метаданных API движка.

---

## Проверено в этом репозитории (дополнение агента, 2026-02-14)

- `.fomain` — это **не** файл прототипа, а главный конфиг движка/игры (`TLA.fomain`) с
  профилями `[SubConfig]`. Прототипы лежат отдельно:
  `Critters/*.focr`, `Items/*.foitem`, `Maps/*.fomap`, диалоги — `Dialogs/*.fodlg`,
  GUI — `Gui/*.fogui`, тексты — `Texts/*.fotxt`.
- Свойства объявляются не в прототипах, а в скриптах метаданными
  `///@ Property <Critter|Item|Map|...> <Server|Client> <тип> <Имя> [Mutable] [Persistent]`,
  например в `Scripts/Behemoth.fos`:
  `///@ Property Critter Server int32 BehemothRadio Mutable Persistent`.
- «Перезапуск генерации метаданных» — это не отдельная ручная операция: генерация идёт
  частью `BakeResources` (через `TLA_Baker` / `TLA_ASCompiler`), а `Scripts/Content.fos` —
  сгенерированный файл, руками его править нельзя.
- Прототипы и сгенерированный контент читаются через `Content::Item::...`, `Content::Critter::...`
  (см. `Scripts/Content.fos`); идентификаторы прототипов — сериализуемый контракт,
  переименование требует миграции.
- Если меняется сериализуемый контракт (свойства, save-данные, сетевые данные,
  генерируемые id контента) — проверь необходимость `///@ MigrationRule` или бампа версии
  конфига (`SourceExt/ContentMigration.cpp`).
- Точные детали сериализации (`PropertiesSerializer`) живут в `Engine/`; в этом репозитории
  их не правят — при расхождении сверяйся с `H:/lf-30` и апстримом submodule.
- После правки контента/скриптов обязателен `Bake Resources`; предупреждения — ошибки.
